# Etymologies

シス単2000語をフラッシュカードで覚えるPWA。
ダイヤル入力で番号を選んで english-battle.com の語源ページを内部表示する v1 機能と、
エビングハウス忘却曲線ベースの学習アルゴリズムを持つフラッシュカード（v2）を統合。

公開URL: <https://puppunosuke.github.io/Etymologies/>

**Google アカウントでログイン**するとクラウド同期が有効になり、PC / スマホ間で進捗が共有される。
ログインしなくてもローカル（端末ごとの localStorage）で完結する。

---

## 単語の学習アルゴリズム

### コンセプト

> **一度でも正解したら次のステージへ進む。間違え続ける限り出題プールに居続ける。**

エビングハウスの忘却曲線をベースにした間隔反復学習。
ステージ（習熟度）が上がるほど次の出題までの間隔が長くなる。

### データモデル

各単語の状態は1枚の「カード」として表現される。

```js
{
  stage: 0..7,      // 習熟度。0 = 未正答（◯を一度も取っていない）。◯で+1、7で頭打ち
  nextDue: string   // 次回出題予定時刻（ISO文字列）。null = 一度も出題されていない
}
```

進捗データ全体は `{ "番号": カード }` の形で localStorage / Firestore に保存される。

### 復習スケジュール（INTERVALS）

`stage` が 1 以上のとき、次回出題までの待ち時間は `stage` で決まる。

| stage | 次回までの間隔 |
|-------|----------------|
| 1     | 20 分後        |
| 2     | 1 時間後       |
| 3     | 9 時間後       |
| 4     | 1 日後         |
| 5     | 2 日後         |
| 6     | 6 日後         |
| 7     | 31 日後（以降ここで頭打ち） |

### 出題ロジック（`pickNext`）

レンジ内の単語から、以下の **1つのプール** に該当するものをランダムに1つ選ぶ。

- **期限到来**: `nextDue ≤ now`（前回の◯から間隔が経過した単語）
- **未正答**: `nextDue == null`（一度も出題されていない or 一度も◯を取っていない単語）

「期限到来」と「未正答」は **同列扱い**。プールに入った単語はどれも等しく出題候補。
出題プールが空（全単語が `nextDue` 未来＝待機中）ならセッション終了通知。

### 評価ロジック（`applyResult`）

| 評価 | `stage` の変化 | `nextDue` の設定 | 意図 |
|-----|----------------|------------------|------|
| ◯  | `stage + 1`（max 7） | `now + INTERVALS[stage-1]` | 習熟度を1段階上げ、待機期間に入れる |
| × | 維持（変化なし） | `now`（即時） | プールに即戻す。◯を取るまでステージは上がらない |

#### 設計上のポイント

- **× で `stage` を下げない**: 「過去の積み上げ（◯ で得たステージ）を失わせない」設計。一度◯を取った難易度感は維持される
- **× で `nextDue = now`**: 即出題プールに戻る。`pickNext` 側の `dueMs <= nowMs` で同時刻も「期限到来」扱い
- **卒業なし**: stage 7 で頭打ちになるが、出題プールからは外れない。永続的に復習ループに残る

### 設計の判断（why）

#### Q. なぜ stage は ◯ のときだけ上がるのか？
「**一度でも正解したら次のステージへ**」がシンプルで分かりやすい設計だから。
× したら **間違え続ける限りプールに居続ける** という挙動が成立する。

#### Q. なぜ「期限到来」と「未正答」を同列にしたか？
両者を別プールにすると「期限到来があれば新規単語は出ない」となり、復習に偏る。
**同列にすれば学習中の単語にも新規単語にも均等にアクセス**できる。

#### Q. なぜ期限の超過時間で優先順位を付けないのか？
`nextDue` がミリ秒単位でばらつくため、「最も期限超過したものを選ぶ」を厳密にやると
**毎回1つの単語が決定的に選ばれる順送り出題**になる（ランダム性が失われる）。
過去にこの仕様で実装したところ「順送りに見える」バグとして発覚し、ランダム選出に統一した。

#### Q. なぜ stage 7 で頭打ちか？
31日間隔を超えると、復習頻度が落ちすぎて忘却が進む。
**長期記憶への定着フェーズ**としてここで固定する（無限に伸ばさない）。

## データの持ち方とプライバシー

- 進捗・履歴・設定はすべて **Google ログインしたユーザー自身の領域** に保存される
  - パス: `/users/{自分のUID}/data/main`（Firestore の1ドキュメントに全データを格納）
- **他のユーザーのデータは一切見えないし、書き込めない**（Firestore セキュリティルールで強制）
- ログインしなければクラウドには何も上がらない（その端末の localStorage に閉じる）

```firestore
// セキュリティルール抜粋
match /users/{userId}/{document=**} {
  allow read, write: if request.auth != null && request.auth.uid == userId;
}
```
